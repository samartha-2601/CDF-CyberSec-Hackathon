
# Hackathon Submission Guidelines

## CDF CyberSec Hackathon
### Intelligent Code Security Challenge

## 1. Required Deliverables

Each participating team must submit:

### A. Public GitHub Repository

Your repository must contain:

- Complete source code
- README with setup instructions
- Instructions to run the tool
- Required dependencies
- Description of AI model integration
- Explanation of major features
- Attribution of reused tools and libraries

Do not commit real API keys or credentials.

### B. Working Security Review Tool

Your tool must demonstrate:

1. Source-code input
2. AI-powered security analysis
3. Vulnerability findings
4. Security explanations
5. Recommended fixes
6. Security report generation

A CLI or web application is acceptable.

### C. Demo Video

Submit a demonstration of your tool.

Recommended duration: 3–5 minutes.

Show:

1. A brief introduction to your tool
2. How to start it
3. How to analyze a codebase
4. Example detected vulnerabilities
5. Recommended secure code fixes
6. Generated security report

Use an accessible video link.

Do not include confidential data in the recording.

### D. Sample Security Report

Submit a report generated by your tool after
analyzing the provided CDF TaskFlow application.

Acceptable formats:

- PDF
- HTML
- Markdown

The report should contain a summary, findings,
severity levels, code locations, and remediation.

## 2. Submission Information

The submission form will request:

- Team name
- Team members
- Primary contact email
- Project/tool name
- Short project description
- GitHub repository URL
- Demo video URL
- Sample report URL
- AI model or provider used
- External tools or libraries used
- Setup instructions or README URL

## 3. Submission Deadline

The official deadline will be announced
during the hackathon kickoff.

Submissions received after the deadline may
be subject to organizer review.

## 4. Evaluation Readiness

Before submitting, verify that:

- Your public GitHub link works.
- Your README is complete.
- The project can be started.
- Any API configuration is documented.
- Your demo video can be opened.
- Your sample report is accessible.
- Your repository contains no real secrets.

## 5. Hidden Evaluation

Organizers may test your tool using an additional
application not shared during development.

Your tool should analyze code generically.

Hardcoded findings specific to CDF TaskFlow
will not receive credit on hidden tests.

If your tool depends on a paid API or special
environment, provide clear instructions and
coordinate with organizers for evaluation access.

## 6. Responsible Use

Only use synthetic or authorized source code.

Do not publish confidential client code, real
credentials, or organizer-only evaluation materials.

Do not deploy the intentionally vulnerable
sample backend.

## 7. Final Submission

Complete the official submission form using the
link provided by the organizers.

Keep your submission artifacts accessible until
judging has concluded.
